# 架构与扩展约定

## 数据流

```text
器材配置 → reducer 参数约束 → CameraParameters（含 pose / focusPoint / tilt / shift）
                                   ├─ optics → 实时读数 / 景深示意图
                                   ├─ camera → 视角 / 机位 / 跟焦
                                   └─ renderer → 投影 / 深度 / 散焦 / 曝光
场景注册表 → SceneDefinition ─────────────────────────────────────┘
键盘 / 指针 / 摇杆 → useCameraControls → pose action ─────────────┘
```

`CameraParameters` 是光学计算与画面使用的唯一参数源；`SimulatorState` 额外保存当前 `sceneId`。切换场景时保留镜头、传感器与曝光，只重构机位并把焦点重新锚定到新场景。UI 通过 reducer 提交变化，不直接操纵 Three.js 相机。renderer 只接受已约束的参数、镜头与视图设置。无后端和外部数据存储，刷新页面恢复默认实验状态。

## 机位与对焦

- `CameraPose` 保存世界坐标位置、偏航角与俯仰角，不保存横滚。偏航 0° 朝向世界 −Z，俯仰为正表示向上看。
- `forwardVector / rightVector / axialDistance / pointOnAxis` 是纯函数，位于 `domain/camera.ts`，可独立测试。
- 拖动、键盘和摇杆都通过 `useCameraControls` 的平滑积分循环写入 `pose` action。`cameraMotion.ts` 用指数速度的解析积分处理全部前台经过时间，再以小步追随旋转，避免低帧率下截掉时间而减慢移动。按键/摇杆变化前先结算旧输入；失焦或隐藏页面时清空输入和速度，避免恢复后跳动。循环只在有输入或仍有速度时运行，静止后停止 requestAnimationFrame。
- 拍摄距离滑块使用「相机到主体中心的水平距离」，通过 `withSubjectDistance` 沿当前方位缩放位置；机位高度单独控制 Y。
- 对焦有两种模式。`focusTracking = true` 时，`focusPoint` 是锚定在世界坐标中的物体点，每次机位变化后按镜头重算 `focusDistanceM`：普通镜头使用轴向距离，倾斜镜头求通过该点的倾斜焦平面光轴截距，鱼眼使用到相机的径向距离；`false` 时固定该距离。点击物体或距离标记会写入世界点。
- 对焦距离被钳制在镜头 `minFocusMeters(lens, focal)` 与 30 m 之间；长焦距会提升最近对焦限制（例如 1200 mm 需 ≥ 1.34 m）。切换镜头时如果超出最近对焦距离，会同步移动焦点世界点。
- 每个场景声明独立的 `poseLimits` 与 `cameraNear/Far`，户外场景使用更宽的移动范围与更远的裁剪平面。
- 光圈按三分之一档取整（`snapAperture`），焦距、ISO、快门由 reducer 统一约束。

## 物理模型

### 画幅与同构图对比

默认切换传感器保持原镜头焦距，体现裁切取景。可选的「画幅对比：保持水平构图」先转为自定义镜头，以统一光圈叶片和解除定焦范围约束；之后切换画幅时保留机位、对焦距离与实际 f 数，按传感器宽度缩放工作像距 `v₂ = v₁·W₂/W₁`，再求 `f₂ = v₂/(1 + v₂/s)`（均用毫米，无穷远取 `1/s = 0`）。因此包括近距对焦呼吸的实际水平视角保持不变，长宽比变化时垂直范围仍会改变。所需焦距或最近对焦距离超出自定义镜头限制时禁用对应画幅；选择其他镜头预设退出对比，鱼眼、移轴和折返不启用该模式。

入瞳直径按 `D = f/N` 计算。相同机位、水平构图和 f 数下，较小画幅使用较短焦距，入瞳与归一化焦外光斑都更小；实时弥散圈和光追孔径继续使用实际焦距、f 数和传感器尺寸，没有额外的画幅虚化系数。读数中的 `N × 裁切系数` 是相同对角构图下的常规景深等效参考，近摄及不同长宽比时有差异，不改变曝光、实际光圈或传感器噪声计算。

- `optics/calculate.ts` 是纯函数模块，不依赖 React、DOM、场景和 Three.js。
- 焦距 / 传感器尺寸 / 弥散圈：毫米；世界 / 对焦 / 拍摄距离：米。
- 标称视角使用无限远像距；渲染与「对焦延伸视角」使用 `v = f·s/(s−f)` 的实际像距，体现对焦呼吸。
- 景深使用薄透镜模型，远界在超焦距处为 `Infinity`，仅在显示层格式化为 `∞`。
- 衍射斑为 `2.44·λ·N`（λ = 550 nm），与几何弥散圈按平方和合成后用于渲染；景深读数仍使用传统几何判据，便于对照教科书公式。
- 曝光使用 `EV₁₀₀`；渲染器以默认场景曝光为参考做归一化，或在恒定曝光模式下固定曝光。
- 无穷远景深保留为 `Infinity`；散焦半径、采样数和像素比例在 `renderer` 内计算，数值光学不依赖渲染质量。

## 镜头与特殊光学

- 镜头库由 `data/equipment.ts` 声明，带 `kind` 分类：`zoom`、`prime`、`fisheye`、`tilt-shift`、`mirror`。覆盖自定义 10–1200 mm f/0.95–32、大三元 / 小三元、常见定焦大光圈、300 f/2.8、600 f/4、移轴、鱼眼与折返。
- 移轴（tilt-shift）在 reducer 中约束 `tiltDeg ∈ [−8.5, 8.5]`、`shiftX/shiftY ∈ [−1, 1]`；渲染器用斜向视锥实现平移，用倾斜焦平面（沿水平轴的平面法线）近似沙姆定律，弥散圈按该射线对应的焦平面距离计算。
- 鱼眼在场景顶点着色器中直接实现等立体角投影 `r = 2f·sin(θ/2)`（通过 `onBeforeCompile` 注入）。片元深度编码到相机的径向距离，并在片元中做径向近/远裁剪，支持中画幅大于 180° 的对角视野。景深、体积光、点击对焦和跟焦沿用径向距离；景深用理想球面焦面近似，未模拟真实鱼眼的像场弯曲和像差。
- 折返（mirror）光圈固定 f/8，散焦核退化为环形孔径，形成甜甜圈光斑。

## 场景

`SceneDefinition` 包含 ID、显示文案、世界坐标距离标记、默认焦点、默认机位、移动范围、近远平面与工厂。工厂收到 `{ renderer }`，用于生成 PMREM 环境贴图；返回独立的 `SceneInstance`、必需的 `sunlight` 固定光源与空气散射参数、完整的 `dispose()`，以及可选的 `setQuality()`。

四个场景各带独立固定光源：

每个场景使用独立太阳参数源与一盏实体灯具聚光源；太阳在实时模式为方向光、在光追模式为远距离圆面，天空环境单独提供补光。`fixtures.ts` 构建可求交的灯罩、发光面、路灯杆与底座，或室内吊灯的顶盘和吊线。湖畔路灯位于现有小径左侧并使用 `terrainHeight` 确定底座高度；人像路灯位于樱花步道右侧、人物之后；知更鸟路灯位于栖枝后方林间步道旁。吊灯顶盘固定在室内天花板下表面 Y = 3.60 m。灯源位于扩散发光面下方，避免灯罩或发光面误挡自身的投射光。太阳和灯具光源分别加入光追灯光列表，灯具网格进入物理场景和 BVH，发光材质保留自发光参数；不再使用无实体的摄影补光灯。

光追场景排除 `visible-sun` 圆盘的所有几何，日轮由解析背景和光追圆面统一呈现。仅设置 `castShadow=false` 不能保证圆盘不遮挡金属的镜面采样路径，因此不可将日轮当成近处实体放入 BVH。交互场景的 `DirectionalLight` 是唯一太阳参数源，光追仅注册一个远距离圆面光源；环境纹理不再额外包含太阳圆面能量。三个室外场景使用侧前方太阳方向 `(-0.40, 0.46, 0.79)` 的单位向量，天空、解析日轮、实时方向光、光追圆面和体积光均使用同一方向；室内保留穿窗方向。室外环境强度为 1，室内保持 0.30；路灯外壳使用金属度 0.08、粗糙度 0.55 的灰绿色喷漆表面，以保留日照下的漫反射与阴影层次。`e2e/sunlight.spec.ts` 在灯泡与天空关闭时测量独立太阳的照明贡献，并验证太阳强度与灯体反射能量的比例。

- **室内静物**：对照窗边陶艺静物参考图；墙体为窗户留出真实开口，窗外枝叶、透明玻璃和木窗格参与遮挡，定向光穿窗照射静物与地面。白花、陶器、茶具、书册与垂坠桌布构成主体。
- **室外高山湖畔**：晴天天气，蓝天、稀疏高云、暖色直射阳光与清晰树荫；太阳圆盘与主光源方向一致，远景只保留轻微蓝色大气透视。真实湖盆与岸线，侵蚀山脊与坡度相关的积雪，针叶林、草甸与野花。`lake.ts` 使用 Reflector 在半浮点目标中捕捉实际山体和树木的平面倒影，合成细波纹与菲涅耳混合；场景释放反射目标，`setQuality` 控制反射分辨率。
- **室外人像**：樱花步道中的着衣人物，取代原雕塑棚。`anatomicalHead.ts` 解码本地 CC0 人体头部，`human.ts` 构建贴合头皮的发帽、分层黑长直发（刘海、脸侧发帘与及腰后发）、眼球与睫毛、水手服 JK（藏青领、红领结、百褶裙）与条纹过膝袜的完整着衣轮廓。`botanical.ts` 提供樱花枝、草地和叶脉材质。参考图用于指导服装、场景与构图，不复刻具体人物身份。
- **林间知更鸟**：晴天林间暖阳，蓝天从树冠空隙透出，太阳圆盘与直射光方向一致；暖色主光照亮鸟身、树皮和叶缘，枝叶参与阴影投射，较弱的蓝色天空补光保留暗部层次。按约 16 cm 的站立高度建模，头部与胸腹使用连续曲面，保留分层飞羽、眼圈、鸟喙与抓枝脚趾；覆苔树枝、地衣、近叶和远林构成前后景。

`references.ts` 引用 `预览/` 下的四张原图，构建后以独立图像资源输出，只在参考图对话框打开时加载显示，不用于覆盖三维画面。

`modeling.ts` 提供曲线管、椭球、圆角实体、平滑陶器和杯状叶片，以及共享资源的去重释放。树冠使用 `InstancedMesh` 绘制独立叶片，针叶树使用不规则分层针叶簇。新增场景使用 `disposeScene` 时，材质贴图、几何体、实例缓冲与灯光阴影都会统一释放；环境渲染目标由场景单独释放。

材质由 `scenes/textures.ts` 在本地生成：可平铺 fBm、木纹、织纹、炻器釉面、纸张、艺术印刷与接触阴影。每个面产出 albedo、法线贴图与可选粗糙度贴图，并按需释放。共用几何（树、草、云、接触阴影、扫掠面、车削面）放在 `scenes/helpers.ts`、`scenes/modeling.ts` 与 `scenes/botanical.ts`。

新增场景时：

1. 在 `src/scenes/` 添加工厂，世界单位为米，声明 `defaultPose`、`poseLimits`、`cameraNear/Far` 与 `defaultFocusPoint`。
2. 返回场景对象和完整的资源释放函数，释放几何体、材质、纹理、环境贴图与阴影资源。
3. 用 `landmarks` 声明有教学意义的物体世界坐标，用 `defaultFocusPoint` 给出推荐焦点。
4. 加入注册表。场景选择器和距离条自动读取注册表，无需把资源逻辑写入 UI。

距离示意图沿当前光轴计算每个标记的 `axialDistance`；位于相机后方的标记会被禁用并标注。由于相机可以自由移动，轨道上界会随当前焦点与所有可见标记动态扩展。

## 渲染管线

`optics/sun.ts` 定义统一太阳角半径与 `E = π L sin²α` 能量关系。交互场景保留方向光作为唯一太阳参数来源；`physicalSun.ts` 将其转换为 `ShapedAreaLight(isCircular=true)`，在 1 亿米距离以真实角直径采样。太阳没有 BVH 网格，沿用库中的面积光直接采样、面积到立体角 PDF、BSDF 命中与 MIS。环境纹理仅含天空，不含太阳圆面。光源方向、颜色、强度或可见性变化会同步更新光追光源并重置累积。

库 0.0.24 不在初始/透射射线中显示解析灯光，`installSolarBackground` 因此只在其 `sampleBackground` 入口补充相同方向、角半径和辐射亮度的日轮，不修改 BSDF/MIS 路径；适配依赖该锁定版本的内部材质入口，布局不兼容时明确失败并触发实时降级。实时 `solarBackground.ts` 使用相机居中的远平面天空背景；`solarDisc.ts` 单独绘制 `solar-disc` 网格，`addVisibleSun` 关闭天空背景内部的日轮，防止重复显示。独立日轮从实际逆投影矩阵重建视线，鱼眼使用等立体角逆投影；太阳位于角度上的无穷远，保持视直径且没有近处代理的视差，在远平面接受几何遮挡但不写深度、不参与点击对焦。`sunlight.model` 与 `sunlight.sun` 通过光源 UUID 关联，可见性、颜色、方向与辐射亮度同源；显示网格排除出光追 BVH，由同源的圆盘光源计算能量。光栅 FP16 显示代理将辐射亮度截到 65000，光追保留原辐射亮度。`solarShadow.ts` 仅替换方向光阴影采样，以线性正交深度差和真实太阳角半径估计 PCSS 半影，聚光灯保持原实现。体积光继续使用原有低成本单次散射，不做完整体积路径追踪。

`SimulatorRenderer` 拥有 WebGLRenderer、透视相机、全分辨率场景目标（HalfFloat + DepthTexture + 可选 4×MSAA）、半分辨率颜色 / 弥散圈 / 模糊目标、两个近景半径扩展目标、预乘近景目标与后处理材质。

1. **场景**：渲染到 HDR 离屏目标，写入线性颜色与深度；鱼眼镜头在此阶段通过顶点着色器做等立体角投影。
2. **降采样**：在 4 个样本中选取最近深度，只平均与之深度相符的颜色，避免提前混入背景颜色。
3. **弥散圈**：从 2×2 深度取最近值，按薄透镜公式（可含倾斜焦平面）与艾里斑计算有符号半径，输出全分辨率像素单位。
4. **近景半径**：对负弥散圈半径做水平 / 垂直最大值扩展，各最多 57 次半径纹理读取，以局部最大半径决定搜索范围。只扩展半径，不扩展颜色。
5. **近景层**：使用对称成对的固定圆盘采样，根据来源弥散圈与光圈形状判断覆盖，按来源光斑面积归一化。排除比接收表面更远的来源，输出预乘 RGB 与覆盖率 alpha；光圈叶片与环形核参与覆盖计算。
6. **底图散焦与补色**：远景汇聚排除近景来源；近景轮廓内部从附近可见的后方表面补色，没有可用背景时保留原颜色。这不能重建完全不可见的背景。
7. **合成**：保留全分辨率焦内底图；按当前像素弥散圈混合底图散焦，再按深度上采样近景层，使用 `base * (1-alpha) + premultipliedRGB` 叠加。随后施加暗角、虚拟传感器噪声、ACES 与 sRGB 输出。

弥散圈和半径纹理使用最近邻过滤，避免正负弥散圈相互抵消。近景层可覆盖自身清晰的背景像素；深度检查减少后景来源对清晰前景的误渗色。最大散焦半径约为画面宽度的 3.4%，上限 56 px；近景层与背景层各使用精细 64 / 均衡 44 / 性能 28 / 流畅 14 个样本。有限采样、半分辨率、单层深度与邻域补色仍会带来细小轮廓和复杂遮挡误差，不能替代薄透镜光追。新增目标随尺寸变化重建，目标与材质均在销毁时释放。

曝光通过 `renderer.toneMappingExposure` 调节。恒定曝光开启时固定为基准曝光；关闭时按 `2^(EV_ref − EV₁₀₀)` 缩放，不截断曝光倍率。曝光仅在最终合成时施加，场景、散焦与光追累积保留未曝光的线性 HDR；改变快门、ISO 或恒定曝光开关不重置光追累积。高光仍可能因 ACES 与显示范围而饱和，这不等于曝光倍率停止变化。暗角强度随光圈与焦距变化。

`optics/sensorNoise.ts` 计算输入噪声系数：光子换算 Q 由快门、光圈和等像素数假设下的传感器面积决定，单位线性颜色的方差为 `L/Q + (2/Q)²`。ISO 增益由曝光阶段统一作用于信号与噪声，不改变光子计数。`renderer/sensorNoiseShader.ts` 提供实时与光追共用的最终输出函数，在实时景深/体积光/暗角之后、光追降噪/体积光之后加入独立 RGB 高斯噪声，再进行曝光、ACES 和 sRGB。噪声不写入 HDR 或光追累积。整数哈希和 Box–Muller 生成样本；参数或机位变化时递增种子，单次采样累积、模式切换与恒定曝光开关不改变种子。预览噪声尺寸按最终输出像素设置，避免光追渲染比例改变颗粒尺寸。

该虚拟模型未做绝对辐射标定，假设等 24 MP、相同量子效率与读出噪声，不模拟真实缩图、Bayer、增益切换、暗电流、量化、满阱或相机降噪，极低计数仍用高斯近似；不能当作实际相机的噪声测试结果。

实时与光追共用 `sunlight.ts` 的阴影判定体积光积分。太阳与灯具光源固定在世界坐标，视线步进受场景深度截断，按高度衰减的介质执行单次散射。`fixtures.ts` 通过 `scenes/sunlight.ts` 的 `addFixedBeam` 创建参与表面光照和阴影投射的灯具聚光源；体积光计算同一光锥、距离平方衰减、柔和边缘与阴影。先解析求出视线进入、离开有限光锥的距离，再在光锥内进行稳定中点积分，避免远景的大步长漏掉窄光束。精细 / 均衡 / 性能 / 流畅分别使用 64 / 64 / 48 / 32 步，再按深度上采样，保留窗格和枝叶切出的光束。

光追使用独立物理场景与薄透镜相机，原始 HDR 累积保留到 128 次采样。`pathTracingDenoise.ts` 在每次完整采样后执行步长 1 / 2 / 4 的三轮 à-trous 滤波，使用相机变化时缓存的深度与表面颜色保护轮廓、纹理和明暗边缘，并由局部亮度方差估计暗部噪声，避免把间接照明中的黑亮颗粒当成边缘保留；强度随采样数减弱。滤波使用两个独立 Float32 目标，避免真实日轮亮度超过 FP16 的 65,504 上限而产生无穷大，不修改累积缓冲，无历史画面混合。最终先叠加体积光，再统一进行 ACES 与 sRGB 输出。物理场景不再包含随机雾体，避免重复散射与低采样体积噪点。体积光仍为基于光栅阴影的单次散射近似。

直线镜头 FOV 使用当前对焦距离对应的实际像距；鱼眼在顶点着色器投影，移轴用斜向视锥。近 / 远距离由场景声明（户外更远）。景深着色器与 CPU 读数使用相同的距离约定：普通镜头为轴向，鱼眼为径向，移轴时以倾斜焦平面为清晰面。`pathTracingFocus.ts` 适配锁定版本的两个光追材质，将库的径向对焦改为轴向焦平面，并把孔径采样光线推进到原近裁剪面；适配与太阳背景钩子组合，入口变化时明确降级。光追降噪的 FP32 目标用最近邻过滤，不依赖可选的 `OES_texture_float_linear`。

## 生命周期与降级

尺寸变化由 ResizeObserver 触发；相机参数变化由 React effect 提交；多次更新合并到一次 requestAnimationFrame，静止时不占用持续渲染循环。自由机位输入本身按帧驱动，移动结束后自动停止。

组件卸载或切换场景时释放 GPU 资源。WebGL 上下文丢失时显示状态并等待恢复；不可创建上下文时保留计算工具，提示三维不可用。四档配置统一定义在 `data/renderQuality.ts`：精细 / 均衡 / 性能 / 流畅按原生取景器宽高的 100% / 85% / 70% / 50% 渲染，默认均衡。统一使用 `devicePixelRatio × resolutionScale` 设置绘制缓冲，光追 `renderScale = 1`，避免二次降采样。精细与均衡使用 4×MSAA，性能与流畅关闭 MSAA；散焦、体积光和湖面反射预算也从四档配置派生。

## 验证

单元测试覆盖视角参考值、裁切系数与中画幅裁切、对焦呼吸像距、衍射、EV 归一化、景深公式、超焦距的无穷远、边界弥散圈一致性、异常输入、机位数学、跟焦约束、光圈分档、鱼眼投影、镜头库覆盖与器材切换约束。此外覆盖四场景的有限几何数据、三角形与绘制数量上限、默认眼部对焦射线、湖岸遮挡、桌布与桌面间距，以及共享资源和实例缓冲释放。

浏览器验证覆盖真实 WebGL 画面、光圈变化、点击对焦、传感器与镜头切换、场景切换、移轴 / 鱼眼 / 折返、自由机位键盘移动 / 转向 / 升降、拖拽环视、虚拟摇杆驱动、机位复位、重置、帮助、移动端溢出和无 WebGL 降级。另有 GPU 数值测试验证光追平面对焦、无浮点线性过滤时的 HDR 降噪、太阳半影、前景景深、曝光与传感器噪声。GitHub Actions 在 PR 与发布前执行类型检查、单元测试、全部桌面浏览器测试与静态构建；托管 Linux 通过 ANGLE/SwiftShader 执行 WebGL2，失败时保存截图与跟踪并阻止发布。`e2e/fixtures.ts` 在 CI 的交互/光追集成测试中把取景 CSS 宽度限制到 320 px，仍运行原有光追采样数、质量比例与着色器；`quality.spec.ts` 保留完整桌面尺寸验证四档原生分辨率。四场景的太阳截图和光追测试各自计时，避免累计耗尽单条测试时限。移动端可在本地运行完整浏览器套件。

键盘运动测试在加载前安装 Playwright Clock，初始化后暂停时间，以固定时长按键和延迟帧验证移动/转向；角度差按 ±180° 回绕计算，避免软件 GPU 的观察延迟让持续按键多转数圈。`pathTracing.spec.ts` 将 28 次实际采样、四档画质切换和光圈变化分别验证；渲染器仅在实际重置累积时递增 `data-path-generation`，测试等待新轮次后才检查采样数，避免沿用旧配置的样本。CI 使用两个独立分片，每片仍只有一个浏览器 worker；`publish` 依赖整个 `verify` 矩阵成功，两片都通过后才构建发布。
